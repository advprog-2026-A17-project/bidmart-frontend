# Non Functional Considerations

## Performance (UX)

| Technique | Location / effect |
|-----------|-------------------|
| Vite code splitting | Dynamic `import()` on heavy routes reduces initial JS |
| React Query cache | Fewer duplicate `GET /listings` calls |
| STOMP patches | Auction UI updates without full page reload |
| Image lazy loading | Listing grids where implemented |

Baseline vs optimized UX scores: [12. Before after perf.md](../../bidmart-infrastructure/docs/12. Before after perf.md) §3.3b (Lighthouse).

## Security

| Control | Implementation |
|---------|------------------|
| OAuth | `GoogleLoginButton.tsx`; public client id only in `VITE_*` |
| JWT | Attached on API calls; not logged to console in production builds |
| STOMP | Bearer on CONNECT; private destinations user-scoped |
| Admin UI | `ProfileGuard` + role checks (server remains authoritative) |
| Push SW | [`public/push-sw.js`](../public/push-sw.js) — scope limited to app origin |

## Reliability

- Playwright `retries` in [`playwright.config.ts`](../playwright.config.ts) for flaky network in CI.
- `useWebSocket` / notification hooks should reconnect after gateway restart (verify during demo).
- Contract tests catch API shape drift before E2E.

## Scalability

- Static `dist/` served via CDN or `serve`; horizontal scale is trivial (stateless assets).
- WebSocket connections scale with gateway + order service capacity, not frontend pods.

## Maintainability

- Module-per-domain under `src/modules/*`.
- Rubric pack `docs/0–7` + `docs/evidence/` for grading.
- SonarCloud on every PR.

## Browser support

- Playwright CI: Chromium.
- Manual demos: headed Chrome (`npm run test:e2e:headed`).
