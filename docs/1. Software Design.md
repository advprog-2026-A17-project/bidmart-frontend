# Software Design (SOLID, Design Patterns)

## Module structure

| Module | Path | Responsibility |
|--------|------|----------------|
| Auth | `src/modules/auth/` | Login, register, 2FA, admin, profile |
| Catalogue | `src/modules/catalogue/` | Browse, sell, listing detail |
| Auction | `src/modules/auction/` | Bidding UI, realtime patches |
| Wallet | `src/modules/wallet/` | Balance, top-up |
| Orders | `src/modules/orders/` | Order list, detail, dispute UI |
| Notifications | `src/modules/notifications/` | Notification center |

## Cross-cutting

- `src/context/AuthContext.tsx` — session state
- `src/hooks/useWebSocket.ts`, `useNotificationRealtime.ts` — STOMP lifecycle
- `src/App.tsx` — route composition, lazy routes where applied

## SOLID (frontend)

### Single Responsibility (SRP)

- Page components orchestrate UI; HTTP lives in `utils/*-api.ts`.
- `auction-realtime-patch.ts` only merges STOMP payloads into cache.

### Open/Closed (OCP)

- New routes registered in `App.tsx` without modifying unrelated modules.
- New listing card variants extend `components/` without changing `SellPage` core.

### Liskov Substitution (LSP)

- Shared `ProfileGuard` / layout wrappers behave consistently for buyer vs seller routes.

### Interface Segregation (ISP)

- Hooks expose narrow APIs (`useNotificationRealtime` vs dumping all STOMP details into pages).

### Dependency Inversion (DIP)

- Leaf components depend on `AuthContext` interface, not `localStorage` directly.
- API modules depend on env-based base URL, not hard-coded service hosts.

## Design patterns (≥3)

### 1. Container / presentation split

Pages under `pages/`; reusable UI in `components/` (e.g. `OrderStatusCard.tsx`, `NotificationCenter.tsx`).

### 2. Custom hooks (composition)

- `useNotificationRealtime.ts` — STOMP subscribe/unsubscribe.
- `useNowTick.ts` — auction countdown ticker.

### 3. Context provider

`AuthContext`, `WalletUIContext` avoid prop drilling for session and wallet modal.

### 4. Adapter utilities

- `src/modules/auction/utils/auction-realtime-patch.ts` — maps STOMP DTO → React Query keys.
- `src/modules/catalogue/utils/listing-to-auction.ts` — catalogue → auction form DTO.

### 5. Contract tests (API adapter)

- `frontend-flow.contract.test.mjs`
- `src/modules/auth/contracts/auth-login-contract.ts`

Guards backend contract without browser (fast CI feedback).

## Realtime design

- SockJS + STOMP (`@stomp/stompjs`) aligned with [11. Keamanan stomp.md](../../bidmart-order-and-notification-service/docs/11. Keamanan stomp.md).
- Public auction topics vs private `/user/queue/notifications`.

## Maintainability

- TypeScript strict build (`tsc -b`).
- ESLint flat config for consistent style.
- E2E specs document critical journeys for regressions.
