# Software Deployment

## Local Development

| Item | Detail |
|------|--------|
| Backend stack | Run `docker compose up` from `bidmart-infrastructure` |
| Frontend dev | `npm run dev` on host, default `http://localhost:5173` |
| Gateway | `http://localhost:8000` |
| Env | Copy `.env.example` to `.env` when overriding gateway/OAuth values |
| Proxy | Vite proxies `/api` and `/ws` to the gateway when `VITE_API_BASE_URL` is empty |

Frontend is run on host during local development to avoid container `node_modules` and memory issues.

## Production Build

```bash
npm ci
npm run lint
npm test
npm run build
```

`npm run build` outputs static assets into `dist/`. The same bundle can be served by Vercel, Heroku static serving, Nginx, or a CDN.

## CI/CD

| Job | Trigger | Steps |
|-----|---------|-------|
| `test` | push / PR | `npm ci`, lint, contract tests, build |
| `e2e-nightly` | scheduled/manual | Playwright against a deployed stack |
| `sonarcloud` | after test | Sonar scan when `SONAR_TOKEN` exists |

CI evidence: `docs/evidence/ci-workflow-success-2026-05-21.png`.

## Vercel Strategy

| Branch | Environment | Platform |
|--------|-------------|----------|
| Pull request / staging | Preview | Vercel preview deployment |
| `main` | Production | Vercel production deployment |

Promotion flow:

1. Merge or open PR.
2. CI validates lint, contract tests, build, and optional Playwright.
3. Vercel deploys preview.
4. Validate UI flow against staging gateway.
5. Promote to `main`.
6. Vercel deploys production after required checks.

Production gateway value:

```text
VITE_API_BASE_URL=https://bidmart-prod.43.157.208.68.sslip.io
```

## Heroku / Static Hosting

- `heroku-postbuild`: `npm run build`
- `npm start`: `serve -s dist -l ${PORT:-4173}`

## Rollback

- Vercel: use instant rollback to a previous deployment.
- Heroku/static hosting: redeploy the previous build artifact or revert commit and redeploy.
- Backend/gateway rollback must be coordinated from `bidmart-infrastructure`.
